# AllMerge GRPO family: unified training visualization & paired-checkpoint evaluation

The main entry lives **in this repository**:

```
scripts/evaluate_rl_training.py
```

It works for Vanilla GRPO, Normalized Lagrangian, Projection and SafeMPO-Diff when their checkpoints contain the AllMerge planner state dictionary. The plotting implementation is in `evaluation/rl_training_report.py`. Nothing should be installed outside `all_merge-grpo`.

## Outputs

- `01_reward_curve.png`: train task reward (raw + moving average), fixed-validation RL/pretrain reward if present.
- `02_loss_curve.png`: total loss, policy loss and SafeMPO distillation loss if available.
- `03_constraint_violation_magnitude.png`: **primary** training per-constraint mean violation magnitudes and maximum violation (train/fixed-val).
- `04_fixed_validation_violation_magnitude.png`: fixed validation mean violation magnitude and RL-minus-pretrain changes (negative = improved).
- `05_constraint_violation_rates_optional.png`: optional training violation fractions and joint feasible fraction (only when logged).
- `06_policy_kl.png`: optional KL diagnostics.
- `07_pretrain_vs_rl_trajectories_3x3.png`: 9 randomly chosen paired states, roles, G48 samples, with the same state, mode and diffusion noise. Sparse points are **not** linked directly; curves are clamped cubic interpolations sampled at 10 Hz.
- `09_paired_trajectory_displacement_3x3.png`: paired RL–pretrain displacement vs time, useful for millimeter-scale improvements.
- `08_paired_constraint_violation_mean.png`: separate paired G48 checkpoint comparison of mean normalized violation magnitudes.
- `paired_eval_per_state.csv`, `gallery_manifest.csv`, `paired_eval_summary.json`, `evaluation_manifest.json`.

### Manual evaluation of an existing checkpoint

Use Windows cmd and execute from `D:\KONG_Files\AllMerge\all_merge-grpo`:

```bat
python scripts\evaluate_rl_training.py ^
  --checkpoint outputs\safempo_diff_v11\both_g48_500\safempo_diff_v11_both_curved500.pt ^
  --pretrain-checkpoint ..\all_merge-gru\outputs\gru_coarse_goal_ablation_30ep\gru_refine_dense\run_1\checkpoints\best.pt ^
  --train-log outputs\safempo_diff_v11\both_g48_500\train.log ^
  --fixed-validation-csv outputs\safempo_diff_v11\both_g48_500\fixed_validation.csv ^
  --scenario curved --num-states 16 --group-size 48 --seed 7 ^
  --task-reward-type progress_comfort ^
  --output-dir outputs\safempo_diff_v11\both_g48_500\visual_evaluation
```

To compare another trained checkpoint, change `--checkpoint`. To generate **only log figures** without checkpoint or simulator, use:

```bat
python scripts\evaluate_rl_training.py ^
  --curves-only ^
  --train-log outputs\safempo_diff_v11\both_g48_500\train.log ^
  --fixed-validation-csv outputs\safempo_diff_v11\both_g48_500\fixed_validation.csv ^
  --output-dir outputs\safempo_diff_v11\both_g48_500\visual_evaluation
```

## Automatic evaluation when training completes

`scripts/run_and_tee_500step.py` runs the visual evaluator **after successful 500-step training**, provided `--checkpoint` (pretrain) and `--output` (trained ckpt) appear in the training command. No changes to the training algorithms are required. Existing G48×500 scripts already using this wrapper acquire automatic evaluation after this patch is installed.

Set `--visual-eval` (before `--`) to explicitly request evaluation for shorter runs, or `--no-visual-eval` to skip it. Adjust state count using `--visual-eval-states 16`; random gallery selection via `--visualization-seed 0`. For example:

```bat
python scripts\run_and_tee_500step.py ^
  --log outputs\my_run\train.log ^
  --visual-eval --visual-eval-states 16 --visualization-seed 0 ^
  -- python train_safempo_diff500.py ^
     --checkpoint ..\all_merge-gru\outputs\gru_coarse_goal_ablation_30ep\gru_refine_dense\run_1\checkpoints\best.pt ^
     --scenario curved --group-size 48 --steps 500 ^
     --output outputs\my_run\trained.pt
```

The wrapper creates an output directory adjacent to the checkpoint, e.g. `trained_visual_evaluation/`. A failed visualization does **not** discard a valid checkpoint or change the training status; check `post_eval.log`, then run manually. For direct calls to `train_*.py` that bypass the tee wrapper, run the evaluator separately.

## Important measurement contracts

* The five violation magnitudes are **normalized residuals** generated by the original W4 constraint function, **not meters/seconds**. Their scales differ across constraints. Do not relabel as violation rates.
* Training state curves are **not** fixed-state learning curves. Only fixed validation or paired checkpoint evaluation can support learning-effect comparisons across steps.
* The optional violation fractions are fractions among sampled valid G48 candidates on the evaluated states, **not deployment collision frequencies**.
* One 9-panel image uses 9 randomly selected states, each paired by fixed diffusion noise, vehicle role, pretrain-selected mode, and sampled group index. The same support/seed is essential to avoid mistaking sampling variance for learning.
* The paired checkpoint task reward defaults to `progress_comfort` (matching current baselines). Specify `--task-reward-type legacy_w4` for older jobs.
* Random gallery seed affects *which panels* are shown, not the trajectory/reward calculation over all `--num-states` states.
* Real model inference requires the project's full dependencies (`torch`, `gymnasium`, `highway_env`, `scipy`) and the actual checkpoint; the plot-only mode does not load those modules.
