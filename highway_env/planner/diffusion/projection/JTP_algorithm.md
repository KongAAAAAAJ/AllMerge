# JTP 伪代码：LS 与 Constrained QP 双后端

1. 计算名义控制序列的执行轨迹、控制范围残差及六类状态约束残差。若全部约束满足，则原样返回。
2. 根据六类状态约束的初始超容差残差和重要性权重计算优先级，固定划分为三组。控制量范围不参与排序和活动集截断。
3. 根据所选求解器构造共享线性化。LS 路径计算轨迹与控制联合度量矩阵；QP 路径只计算状态约束 Jacobian，不计算 LS 专用度量矩阵。
4. LS 后端首先通过阻尼加权 Cholesky 方法恢复控制范围，再顺序求解三个状态约束组，并使用 Trust Region 与度量半空间投影保护前序组。
5. QP 后端首先使用控制修正幅度目标和控制量硬边界恢复可执行控制范围。随后按优先级顺序求解三个 QP：
   - 目标函数只惩罚控制增量，以及当前组状态松弛和前序组保护松弛；
   - 当前组活动状态约束写为 `r + J d <= s`，并满足 `0 <= s <= r`；
   - 前序组全部已选活动行写为 `H_prev d <= xi`，并满足 `0 <= xi <= protection_tolerance`；
   - 每个子问题均施加最终控制量范围硬约束；
   - QP 不设置 Trust Region，也不设置组级最低改善比例。
6. 两个后端均将累计修正量交给同一非线性 Backtracking。线搜索期间冻结道路关联；候选必须满足控制量硬约束、逐约束非退化和各优先级组违反数量不增加，并取得实际状态改善，除非候选正在恢复原本不可执行的控制量。
7. 候选接受后重新计算执行状态、约束和道路关联；达到可行、迭代预算或停滞上限后返回最后接受的控制序列及对应执行预测。

QP 求解失败时记录 OSQP 状态与残差，不自动切换至 LS。完整道路和碰撞非线性验证、K2 执行模型及评估接口保持不变。
